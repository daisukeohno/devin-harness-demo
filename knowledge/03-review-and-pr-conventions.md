---
name: "Sensor analytics: PR とレビューの進め方"
scope: "sensor-analytics で PR を作る、レビュー指摘に対応する、リリースを準備するとき"
---

- ブランチ名は `devin/<epoch>-<short-topic>`。
- PR は 1 テーマ 1 本。解析ロジックの変更と整形・リネームを混ぜない。
- 解析結果の数値が変わる変更は、PR 本文に変更前後の比較を必ず載せる（対象デバイス、`n_samples`、平均、異常検知件数）。
- `config.py` の既定値を変える PR は、影響を受ける既存の運用レポートを列挙する。
- レビュー指摘のうち、単位・タイムゾーン・データリークに関するものは blocking として即対応する。スタイルの好みは `ruff` の設定変更として別 PR にする。
- CI（lint + pytest）が緑になるまでマージしない。落ちている場合、原因を特定せずに再実行しない。

## 承認が必要な操作

- サンプルデータの追加・差し替え
- 依存関係の追加
- API レスポンスの項目削除・改名
- リリースタグの作成
